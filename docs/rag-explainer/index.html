RAG System: Architecture, Build, Pipeline aur Functioning

Retrieval-Augmented Generation (RAG) ko shuru se samjho: ye kya hai, iske andar kya-kya hota hai, aur Knowledge-Vault mein ise kaise banayenge. Saath mein diagrams, ek live demo aur Python code bhi hai.

01

RAG kya hai, aur kyun chahiye?

LLM (jaise Claude ya GPT) bahut accha likhta hai, par uski memory training ke time tak hi hoti hai. Use aapka syllabus, aapke PDFs ya aaj ki khabar nahi pata. Aur jab use koi baat nahi pata hoti, tab bhi wo confidently galat jawab de sakta hai. Ise hallucination kehte hain.

📕

Sirf LLM = Closed-book exam

Student ko sirf yaad se likhna hai. Jo yaad nahi, wo guess karega. Kabhi sahi, kabhi galat, aur koi source nahi.

📗

RAG = Open-book exam

Pehle book se sahi page dhoondo (Retrieve), phir us page ko padh kar apne shabdon mein jawab likho (Generate), aur saath mein page number cite karo.

Ek line mein: RAG = Retrieval (sahi jaankari dhoondhna) + Augmentation (use prompt mein jodna) + Generation (LLM se jawab likhwana).

RAG ke 4 bade fayde

✅ Kam hallucination

LLM sirf diye gaye context se likhta hai, isliye bana-banaya jawab kam deta hai.

🔄 Hamesha up-to-date

Naya syllabus aaya? Bas naye documents index karo. Model ko dobara train nahi karna padta.

🔗 Citations

Har jawab ke saath source link hota hai, isliye uski jaanch ho sakti hai.

💰 Sasta

Fine-tuning ke muqable bahut sasta. Koi GPU nahi chahiye, sirf API calls.

02

RAG ka Architecture

Har RAG system do hisson mein bata hota hai. Indexing pipeline ek baar pehle (offline) chalti hai aur knowledge ko taiyaar karke rakhti hai. Query pipeline har sawaal par (online) chalti hai aur jawab banati hai.

Architecture ke 6 main components

ComponentKaamHum kya use karenge
Document LoaderPDF, websites, notes se text nikalnapypdf, trafilatura, BeautifulSoup
Text Splitter (Chunker)Lambe text ko chhote overlapping tukdon mein todnaRecursive splitter, 300-500 tokens, overlap ~50
Embedding ModelHar chunk ko ek number-vector (meaning) mein badalnasentence-transformers (all-MiniLM / bge)
Vector DatabaseVectors store karna aur fast similarity searchChromaDB (local), pgvector (Supabase)
Retriever + Re-rankerQuery ke liye best chunks dhoondhna aur unhe order karnaVector + BM25 (hybrid), cross-encoder re-ranker
Generator (LLM)Context padh kar jawab likhna, citations ke saathClaude API
03

Pipeline step-by-step (interactive)

Har step par click karo. Dekho us step mein kya andar jaata hai, kya bahar aata hai, aur andar kya hota hai. Example topic: "Shadow Paging" (DBMS Unit 5).

INDEXING

Step 1: Load (documents laana)

Sabse pehle saare sources ikattha karo: textbook PDFs, NPTEL notes, GeeksforGeeks / Wikipedia pages, aur university ke syllabus PDFs. Har document ke saath metadata bhi rakho (source URL, subject, unit), jo baad mein citation aur filtering ke kaam aata hai.

InputURLs, PDF files
OutputRaw text + metadata {url, subject, unit}
INDEXING

Step 2: Clean (safai)

Web pages mein menus, ads, footers, "Read more" jaisa kachra hota hai. trafilatura sirf main article text nikalta hai. Iske baad duplicate paragraphs hatao, aur extra spaces aur galat encoding theek karo. Kachra andar gaya, toh kachra hi bahar aayega, isliye ye step bahut zaroori hai.

InputRaw HTML / PDF text
OutputSaaf, padhne layak text
INDEXING

Step 3: Chunk (tukde karna)

Poora document LLM ko ek saath nahi de sakte. Isliye text ko 300-500 tokens ke tukdon mein todo, aur har tukde mein pichhle tukde ke ~50 tokens overlap rakho, taaki koi sentence beech mein na kat jaaye. Headings ke hisaab se todna (recursive splitting) sabse accha rehta hai.

Input1 document (5000 words)
Output~25 chunks, har ek par id + metadata
INDEXING

Step 4: Embed (meaning ko number banana)

Embedding model har chunk ko ek vector (jaise 384 numbers) mein badalta hai. Jinka matlab milta-julta hai, unke vectors paas-paas hote hain, chahe shabd alag hon. Jaise "shadow paging" aur "copy-on-write page table" ke vectors kareeb honge.

Input"Shadow paging keeps two page tables..."
Output[0.12, −0.48, 0.33, … 384 numbers]
INDEXING

Step 5: Store (vector DB mein rakhna)

Har chunk ka vector, uska text aur metadata ek vector database mein save karo. Vector DB ek special index (HNSW) banata hai, jisse lakhon vectors mein bhi milliseconds mein search ho jaata hai.

Inputvectors + text + metadata
OutputSearchable knowledge store
QUERY

Step 6: Query aur query rewriting

User (ya hamara Writer agent) sawaal poochta hai: "Explain shadow paging with advantages." Behtar results ke liye LLM se query ke 2-3 alag roop bhi banwa sakte hain ("shadow page table recovery", "copy-on-write DBMS recovery"). Is technique ko multi-query kehte hain. Phir query ko usi embedding model se vector banao.

InputUser ka sawaal
OutputQuery vector(s)
QUERY

Step 7: Retrieve (milte-julte chunks dhoondhna)

Vector DB query vector se sabse kareeb top-k (jaise 20) chunks laata hai, cosine similarity se. Saath mein BM25 keyword search bhi chalao, jo exact shabd ("ARIES", "WAL") pakadta hai. Dono ko milana hybrid search kehlata hai.

InputQuery vector
Output20 candidate chunks + scores
QUERY

Step 8: Re-rank (sabse acche chunks chunna)

Pehli search tez hai par thodi motti-motti hai. Cross-encoder re-ranker query aur har chunk ko saath padh kar ek accurate score deta hai, aur hum sirf top 3-5 rakhte hain. Isse irrelevant context hat jaata hai aur LLM ka kharcha bhi kam hota hai.

Input20 chunks
OutputBest 4 chunks, sahi order mein
GENERATION

Step 9: Augment (prompt banana)

Ab ek prompt banao jisme ho: instructions ("sirf diye gaye context se likho, har fact ke baad [n] cite karo, na pata ho toh bolo"), context chunks (number ke saath) aur user ka sawaal. Yahi "Augmented" hissa hai.

InputQuery + 4 chunks + rules
OutputEk bada, structured prompt
GENERATION

Step 10: Generate (jawab likhna)

LLM (Claude) prompt padh kar jawab likhta hai, jaise "Shadow paging ek recovery technique hai jo do page tables rakhti hai [1]..." Output ko JSON format mein maango, taaki seedha PDF / e-book renderer mein jaa sake. Iske baad Verifier check karega ki har claim source se support hota hai ya nahi.

InputAugmented prompt
OutputAnswer + citations (JSON)
04

Retrieval kaise kaam karta hai? (Embeddings + Similarity)

RAG ka dil retrieval hai. Agar galat chunk aaya, toh sabse accha LLM bhi galat likhega. Do vectors kitne milte-julte hain, ye cosine similarity se naapa jaata hai:

cos(θ) = (A · B) / (‖A‖ × ‖B‖) → 1 = bilkul same meaning, 0 = koi rishta nahi
Live demo (asaan version) Neeche query type karo. Ye demo shabdon ke overlap se similarity nikalta hai (asli system meaning-based embeddings use karta hai), par idea same hai: jo chunk query se sabse zyada milta hai, wo top par aata hai.

Retrieval quality badhane ki techniques

TechniqueKya karti haiKab use karein
Hybrid searchVector (meaning) + BM25 (exact shabd) ke scores milanaTechnical terms, codes (BCS-501, ARIES)
Multi-queryEk sawaal ke 3-4 roop bana kar search karnaJab user ka sawaal adhoora ho
HyDEPehle ek nakli jawab likhwao, phir us jawab se search karoChhote ya ajeeb sawaal
Re-rankingCross-encoder se top-20 ko dobara score karnaHamesha (sabse bada quality boost)
Metadata filterSirf subject = DBMS, unit = 5 ke chunks dhoondhnaJab syllabus ki structure pata ho (hamare case mein hamesha)
Parent-child chunksChhota chunk se search, bada parent section LLM ko doJab poora context chahiye

06

Knowledge-Vault mein RAG kaise lagega?

Knowledge-Vault ek multi-agent Agentic RAG hai. Har agent ek "editorial team" ke member jaisa hai, aur sabka output ek structured JSON hai jo agle agent ko jaata hai.

Ek topic ki poori journey ("Shadow Paging")

PlannerSyllabus padh kar topic banata hai: {unit: 5, topic: "Shadow Paging", marks: 7, type: "theory+diagram"}
ResearcherSearch queries banata hai ("shadow paging DBMS recovery", "shadow page table advantages"), 8-10 pages laata hai, unka text saaf karta hai, aur trusted sources (NPTEL, university notes, textbooks) ko upar rank karta hai.
Knowledge StoreUn pages ke chunks banata hai, unke embeddings ChromaDB mein daalta hai, aur metadata mein subject=DBMS, unit=5 likhta hai.
PYQ AnalyserPichhle papers mein ye topic 4 baar aaya hai, isliye ★★★ (high importance) deta hai.
WriterTop-4 chunks retrieve karke topper format mein answer likhta hai: Definition, Diagram (Graphviz), Working, Table, Adv/Disadv, Conclusion. Har fact ke saath [1][2] citations hote hain.
VerifierAnswer ko 15 chhote claims mein todta hai, har claim ko source se match karta hai. "Shadow paging needs UNDO" jaisa claim galat nikla, toh Writer ko wapas bhejta hai.
RendererVerified JSON se A4 PDF, HTML e-book, 5 flashcards aur 3 MCQs banata hai.

Agents ke beech data ka format (JSON contract)

  "topic": "Shadow Paging", "unit": 5, "marks": 7, "importance": 3,

  "verified": true, "faithfulness": 0.94

Neeche har component ka chhota, chalne layak code hai. Inko jodne se ek working RAG ban jaata hai. Ye code samjhane ke liye simple rakha gaya hai, production mein error handling aur caching jodo.

# researcher.py: web se sources laana aur saaf karna
import requests, trafilatura, os

def web_search(query, n=8):
    r = requests.post("https://api.tavily.com/search", json={
        "api_key": os.environ["TAVILY_API_KEY"], "query": query, "max_results": n})
    return [x["url"] for x in r.json()["results"]]

def fetch_clean(url):
    html = trafilatura.fetch_url(url)
    text = trafilatura.extract(html) or ""    # sirf main article text
    return {"url": url, "text": text}

docs = [fetch_clean(u) for u in web_search("shadow paging DBMS recovery")]
docs = [d for d in docs if len(d["text"]) > 500]   # bahut chhote pages hatao
# chunker.py: overlapping chunks banana
def chunk_text(text, size=400, overlap=60):
    words, chunks, i = text.split(), [], 0
    while i < len(words):
        chunks.append(" ".join(words[i:i + size]))
        i += size - overlap                     # overlap se context nahi tootta
    return chunks

records = []
for d in docs:
    for j, c in enumerate(chunk_text(d["text"])):
        records.append({"id": f"{d['url']}#{j}", "text": c,
                        "meta": {"url": d["url"], "subject": "DBMS", "unit": 5}})
# store.py: embeddings banana aur ChromaDB mein rakhna
import chromadb
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("all-MiniLM-L6-v2")       # 384-dim vectors, CPU par chalta hai
db = chromadb.PersistentClient(path="./kv_store")
col = db.get_or_create_collection("dbms", metadata={"hnsw:space": "cosine"})

col.add(
    ids=[r["id"] for r in records],
    documents=[r["text"] for r in records],
    metadatas=[r["meta"] for r in records],
    embeddings=model.encode([r["text"] for r in records]).tolist(),
)
# retriever.py: search + re-rank
from sentence_transformers import CrossEncoder
reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2")

def retrieve(query, k=20, final=4, unit=None):
    where = {"unit": unit} if unit else None          # metadata filter
    res = col.query(query_embeddings=model.encode([query]).tolist(),
                    n_results=k, where=where)
    cands = list(zip(res["documents"][0], res["metadatas"][0]))
    scores = reranker.predict([(query, c[0]) for c in cands])
    ranked = sorted(zip(scores, cands), key=lambda x: -x[0])
    return [c for _, c in ranked[:final]]             # best 4 chunks
# writer.py: context ke saath Claude se answer likhwana
import anthropic
client = anthropic.Anthropic()                       # ANTHROPIC_API_KEY env se

RULES = """You write AKTU 7-mark exam answers.
Use ONLY the numbered context. Cite every fact as [n].
If the context is not enough, say "INSUFFICIENT CONTEXT".
Format: Definition, Working (points), Table, Advantages/Disadvantages, Conclusion."""

def write_answer(question, chunks):
    context = "\n\n".join(f"[{i+1}] ({m['url']})\n{t}" for i, (t, m) in enumerate(chunks))
    msg = client.messages.create(
        model="claude-sonnet-5-5", max_tokens=2000, system=RULES,
        messages=[{"role": "user",
                   "content": f"CONTEXT:\n{context}\n\nQUESTION: {question}"}])
    return msg.content[0].text

chunks = retrieve("Explain shadow paging with advantages", unit=5)
print(write_answer("Explain Shadow Paging. [7 Marks]", chunks))
# verifier.py: har claim ko source se check karna (FActScore jaisa)
import json

def verify(answer, chunks):
    context = "\n\n".join(f"[{i+1}] {t}" for i, (t, _) in enumerate(chunks))
    prompt = ("Split the ANSWER into atomic factual claims. For each claim say if the "
              "CONTEXT supports it. Return JSON: "
              '[{"claim": "...", "supported": true/false}]\n\n'
              f"CONTEXT:\n{context}\n\nANSWER:\n{answer}")
    msg = client.messages.create(model="claude-sonnet-5-5", max_tokens=2000,
                                 messages=[{"role": "user", "content": prompt}])
    claims = json.loads(msg.content[0].text)
    score = sum(c["supported"] for c in claims) / len(claims)
    bad = [c["claim"] for c in claims if not c["supported"]]
    return score, bad                               # score = faithfulness
# pipeline.py: sab ko jodna (Writer ↔ Verifier loop)
def generate_topic(question, unit, max_rounds=3):
    chunks = retrieve(question, unit=unit)
    answer = write_answer(question, chunks)
    for _ in range(max_rounds):
        score, bad = verify(answer, chunks)
        if score >= 0.9:                            # 90% claims supported → pass
            return {"answer": answer, "faithfulness": score, "verified": True}
        answer = write_answer(question + f"\nFix these unsupported claims: {bad}", chunks)
    return {"answer": answer, "faithfulness": score, "verified": False}  # human review

09

Common problems aur unke solutions

❌ Galat chunks aa rahe hain

Fix: re-ranker lagao, metadata filter (subject/unit) use karo, chunk size chhota karo, hybrid search chalao.

❌ LLM context ke bahar ki baat likh raha hai

Fix: strict system prompt ("ONLY use context"), har fact par citation maango, aur Verifier loop lagao.

❌ Jawab adhoora hai

Fix: multi-query retrieval, top-k badhao, parent-chunk retrieval, aur agent ko "kya missing hai?" sochne do.

❌ Numericals galat hain

Fix: numericals ko Python code chala kar dobara solve karo (jaise humne backprop aur K-Means ke liye kiya tha).

❌ API kharcha zyada

Fix: embeddings aur search results cache karo, simple steps ke liye chhota model use karo, aur re-rank karke kam context bhejo.

❌ Copy-paste / copyright

Fix: sources sirf samajhne aur citation ke liye use karo, LLM ko "apne shabdon mein likho" bolo, aur open sources (NPTEL, Wikipedia) ko pehle rakho.
